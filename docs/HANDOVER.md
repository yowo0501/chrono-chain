## 3. 기획 핵심과 확정된 결정

### 3-1. 사용자가 직접 밝힌 방향 [사용자발언]

1. 이 게임은 먼저 **아주 기본적인 JRPG**를 만들고, 그 위에 사용자의 **독창적인 시스템·스토리·세계관**을 쌓아 가는 순서로 진행한다.
2. 레퍼런스: 패미컴/슈퍼패미컴 시절 드래곤퀘스트 1~6, 파이널판타지 1~6. RPG Maker류 쯔꾸르 게임과도 일맥상통하는 느낌.
3. 2D 필드에서 도트 캐릭터가 상하좌우로 돌아다니는 방식.
4. 코드는 Claude가 담당한다 (이전 Unity 프로젝트 세 개와 같은 방식).
5. 엔진 후보(Unity / GameMaker / Godot / RPG Maker)를 비교한 뒤 **Godot으로 결정**했다 (사용자가 선택). 참고로 Claude는 RPG Maker가 이벤트·GUI 중심이라 "코드는 Claude가 담당"하는 방식과 결이 다르다고 설명했다.
6. 첫 필드는 **밤의 도시** 모티브, 아주 기본적인 수준.
7. 주인공은 사용자가 제공한 일러스트를 JRPG 도트 형식으로 변환한 것.
   - 일러스트 설명(이미지를 보고 적은 것): 검은 뾰족 머리의 웃는 소년, 남색 테두리가 있는 검은 도복풍 상의와 통 넓은 검은 바지, 회색 허리띠, 가슴의 원형 문양, 검은 신발, 손에 회색 쇠사슬.
8. 작업 방식: 사용자는 Godot 에디터에서 실행·확인하고 피드백을 준다. Claude가 코드/에셋을 만들고 커밋·푸시까지 한다.

### 3-2. 아직 정해지지 않은 것 [코드확인 + 사용자발언]

스토리, 세계관, 고유 시스템, 등장인물(주인공 이름 포함), 전투 규칙, 성장/장비 체계는 **사용자가 아직 제공하지 않았고** 저장소에도 없다 (`data/` 폴더는 비어 있음). 임의로 채우지 말고 사용자에게 물을 것.
게임 이름 "Chrono Chain"의 의미, 주인공 쇠사슬 소품과의 연관 여부도 확인된 바 없다 [추측].

### 3-3. Claude가 정한 설계값 [Claude결정]

| 항목 | 값 | 이유(Claude 설명) |
|---|---|---|
| 타일 크기 | 16x16 px | FC/SFC 필드 표준 |
| 내부 해상도 | 256x224 | SNES 표준. 처음 잡았던 320x180(16:9)에서 교체 |
| 실제 창 크기 | 1024x896 (4배) | 사용자가 "너무 작다"고 해서 추가. 내부 해상도는 그대로 |

## 5. 구조와 연결 관계 [코드확인]

```
chrono-chain/                      ← 저장소 루트 (project.godot 위치)
├─ project.godot                   설정. 메인 씬 = res://scenes/main/main.tscn
├─ README.md                       (일부 낡음 — 8장)
├─ docs/
│  ├─ MECHANICS.md                 v0.1 설계 문서 (일부 구현과 다름)
│  └─ HANDOVER.md                  이 문서
├─ scenes/
│  ├─ main/main.tscn               진입 씬. Field + Player + Camera2D 조립
│  ├─ field/Field.tscn             Node2D + field.gd
│  └─ player/Player.tscn           Node2D + player.gd, 자식 Sprite2D "Sprite"
├─ scripts/
│  ├─ field.gd                     맵 데이터, 타일 스프라이트 생성, is_blocked()
│  └─ player.gd                    입력, 칸 이동, 애니메이션 프레임 선택
├─ assets/
│  ├─ sprites/hero_walk.png        64x32 (4열 x 2행, 셀 16x16)
│  └─ tilesets/night_city_tiles.png  96x16 (6타일 가로 일렬)
└─ tools/
   ├─ gen_hero_sprite.py           hero_walk.png 생성 (저장소 루트에서 실행)
   └─ gen_night_city_tiles.py      night_city_tiles.png 생성
```

### 런타임 씬 트리

```
Main (Node2D)
├─ Field  (field.gd, 그룹 "field" 가입)  ← 자식으로 타일 Sprite2D 280개를 _ready에서 생성
└─ Player (player.gd, 시작 위치 (160, 96) = 격자 (10, 6))
   ├─ Sprite (Sprite2D, hframes=4, vframes=2, centered=false)
   └─ Camera2D (current, 스무딩 꺼짐, limit 0,0 ~ 320,224)
```

### 연결 방식

- Player는 `_ready`에서 `get_tree().get_first_node_in_group("field")`로 Field를 찾는다. NodePath나 시그널은 쓰지 않는다.
- 이동 전 `field.is_blocked(Vector2i)`를 호출해 막힌 칸이면 이동하지 않는다. 맵 밖은 막힌 것으로 취급.
- 입력은 Godot 기본 액션 `ui_up/ui_down/ui_left/ui_right`(커스텀 Input Map 없음)를 매 프레임 폴링한다. 동시에 눌렀을 때 우선순위는 down > up > left > right.

### 맵 범례 (`field.gd`의 `MAP`)

| 문자 | 타일 | 통행 |
|---|---|---|
| `.` | 도로 | 가능 |
| `,` | 보도 | 가능 |
| `#` | 건물 벽 | 불가 |
| `L` | 불 켜진 창 | 불가 |
| `D` | 꺼진 창 | 불가 |
| `P` | 가로등 | 불가 |

### 스프라이트시트 규약

- `hero_walk.png`: 열 순서 = 아래, 왼쪽, 오른쪽, 위. 행 0 = 기본 프레임, 행 1 = 걷기 프레임. 프레임 번호 = `행 * 4 + 열`
- 왼쪽 스프라이트는 오른쪽 프레임을 좌우 반전해서 생성 (`gen_hero_sprite.py`)
- `night_city_tiles.png`: 열 순서 = 도로, 보도, 벽, 켜진 창, 꺼진 창, 가로등 (`field.gd`의 `TILE_COLUMN`과 일치해야 함)

## 6. 실행 방법

1. Godot 4.7 Standard 설치 후 프로젝트 매니저에서 Import → 1장의 `project.godot` 선택 [코드확인: README와 동일]
2. F5(재생 버튼)로 메인 씬 실행. 방향키로 이동
3. 현재 열린 씬만 실행하려면 F6
4. 에셋을 다시 만들려면 저장소 루트에서 `python3 tools/gen_hero_sprite.py`, `python3 tools/gen_night_city_tiles.py` (Pillow 필요)
5. Godot 에디터가 열린 상태에서 외부에서 파일을 바꾸면 에디터가 못 따라오거나 `project.godot`를 자기 형식으로 다시 저장할 수 있다. 외부 수정 후에는 에디터에서 다시 불러올 것

## 7. 실제로 확인된 동작 범위

### 사용자가 직접 보고한 것 [사용자발언]

- 프로젝트를 Godot으로 여는 데 성공했다.
- 처음 실행하자 `player.gd` 53행에서 "Cannot infer the type of "target" variable" 오류가 났다 → `var target: Vector2i = ...`로 수정해 커밋했다.
- 수정 후 사용자는 "창 크기와 맵이 너무 작아서 보이지 않는다"고 보고했다. 즉 **실행 자체는 된 것으로 보인다** [추측: 보고 내용으로 미루어 본 것].
- 이후 창을 4배로 키우는 설정을 넣었지만, **그 뒤의 재실행 결과는 보고받지 못했다.**

### 확인되지 않은 것

- 4방향 이동, 벽 충돌, 걷기 애니메이션, 카메라 경계 동작이 의도대로인지 → 코드상으로는 의도대로 보이나 **실행 확인 없음**
- 4배 창이 사용자 화면에서 제대로 뜨는지
- 스프라이트와 타일의 시각적 품질에 대한 사용자 평가

## 8. 알려진 오류와 미완성

### 8-1. 코드로 확인된 결함·불일치 [코드확인]

1. **정지 시 기본 프레임으로 돌아오지 않는다.** `_update_sprite(false)`는 막힌 칸을 향했을 때만 호출된다. 이동이 끝나도 마지막 걷기 프레임이 그대로 남는다 (`player.gd` 83~90행 부근). `MECHANICS.md`의 "정지 프레임 유지" 서술과 다르다.
2. **카메라가 타일 중앙이 아니라 좌상단을 중심으로 잡는다.** Sprite가 `centered=false`이고 Camera2D가 Player 원점(타일 좌상단)에 붙어 있어서 캐릭터가 화면 중앙에서 오른쪽 아래로 8px 치우쳐 보일 것이다 (추정 아님, 구조상 그렇다. 시각 확인은 못 함).
3. **카메라 제한값이 하드코딩** (`limit_right=320`, `limit_bottom=224`). `Field`에 `width()`/`height()`가 있지만 쓰이지 않는다. 맵을 바꾸면 수동으로 고쳐야 한다. 세로는 맵 높이(224)가 화면 높이(224)와 같아 세로 스크롤이 없다.
4. `player.gd`의 `_unhandled_input`은 아무 일도 안 하는 빈 함수(잔재).
5. 이동 중 입력 버퍼가 없다. 이동이 끝난 뒤의 프레임에서 다시 키를 읽는다.
6. 충돌이 `Field.is_blocked()`의 문자열 조회뿐이라 NPC·적·오브젝트 같은 동적 장애물은 이 구조로는 처리되지 않는다 (확장 필요).
7. 문서가 낡았다:
   - `README.md` 실행 방법 3번이 "콘솔에 `engine bootstrap OK` 출력"이라고 하지만 해당 코드는 삭제되었다. 폴더 구조에 `docs/`, `tools/`도 빠져 있다.
   - `docs/MECHANICS.md`는 "TileSet physics layer로 충돌 처리", "맵 20x15"라고 쓰여 있으나 실제는 TileSet 없이 논리 조회, 맵 20x14다. **코드를 기준으로 삼을 것.**
8. **미추적(커밋 안 된) 파일 4개**: `assets/sprites/hero_walk.png.import`, `assets/tilesets/night_city_tiles.png.import`, `scripts/field.gd.uid`, `scripts/player.gd.uid`. Godot이 자동 생성한 것이며 Godot 4에서는 커밋하는 것이 일반적이다. 아직 결정하지 않았다.
9. `project.godot`에 `window/stretch/aspect`가 없다. 처음엔 `"keep"`을 직접 적었으나 Godot이 다시 저장하면서 지워졌다. 기본값이 keep이라 같은 동작으로 알고 있다 [추측: 공식 문서로 재확인하지 않음].
10. 스프라이트는 극도로 단순화되어 있다. 쇠사슬은 오른쪽을 볼 때 손 옆 2픽셀 정도로만 표현되고, 걷기 프레임은 2장뿐이다. 레퍼런스 일러스트와는 많이 다르다.
11. 테스트 코드와 CI가 없다.

### 8-2. 환경·운영상 주의

- **토큰 노출:** 사용자 PC의 저장소 `.git/config`에서 `origin` URL에 GitHub Personal Access Token이 그대로 들어 있다 [코드확인, 토큰 값은 이 문서에 적지 않음]. 이 토큰은 사용자가 채팅창에 붙여 넣은 것이기도 하다. 인수인계 후에는 폐기·재발급하고, 원격 URL에서 토큰을 빼는 것을 권한다. 토큰의 만료일은 확인하지 못했다 (7~30일 권장했으나 실제 설정은 모름).
- **푸시 경로:** Claude 클라우드 샌드박스의 git은 이 저장소로 푸시할 수 없다(프록시 정책으로 403). 읽기/clone은 된다. 사용자 PC의 연결 폴더에서 실행한 git 푸시는 성공했다 [코드확인: 마지막 푸시 `a92c895`]. 다른 AI 환경에서는 사정이 다를 수 있다.
- **폴더 이중 구조:** 연결된 폴더는 `chrono-chain-godot-setup`이고 저장소 루트는 그 안의 `chrono-chain/`이다 (압축 해제 과정에서 중첩됨).
- **파일 모드:** 그 마운트에서는 모든 파일이 "변경됨"으로 보이는 문제가 있어 해당 저장소 로컬 설정에 `core.fileMode=false`를 넣어 두었다.
- **git 잠금 파일 함정:** 사용자 PC의 연결 폴더는 기본적으로 파일 삭제가 막혀 있어(세션마다 사용자 승인 필요), 커밋 때 git이 남기는 `.git/index.lock`, `HEAD.lock`, `objects/maintenance.lock`, `objects/*/tmp_obj_*`를 지우지 못하는 일이 있었다. 남은 `index.lock`이 있으면 이후 `git add`/`commit`이 "File exists"로 실패한다. 이때는 삭제 권한을 요청한 뒤 해당 파일만 지우면 된다. 2026-10-04 기준으로는 모두 정리해 둔 상태다 [코드확인].
- **커밋 정보:** 해당 저장소 로컬 설정의 작성자는 `Claude <noreply@anthropic.com>`이다. 세션 환경의 커밋 서명 확인 훅 때문이며, 커밋 메시지 끝에 세션이 요구하는 `Co-Authored-By` 줄을 붙여 왔다.
- **창 크기:** 1024x896 창은 세로 해상도가 900 미만인 화면에서는 화면을 넘을 수 있다 [추측].

## 10. 사용자와 일하는 방식 [사용자발언 + 대화 관찰]

- 사용자는 한국어로 소통한다. 이전 Unity 프로젝트 세 개(트리플 스타즈, 드론 서커스, 스페이스 브레이커)를 Claude와 함께 만들었다.
- 에디터 조작(버튼 위치, 단축키)을 자주 묻는다. UI 안내는 구체적으로 써 줄 것.
- 사용자는 오류 메시지를 그대로 붙여 넣어 보고한다. 에러가 오면 해당 줄을 열어 원인을 찾아 고치고, 같은 종류의 문제가 다른 곳에 없는지 함께 확인한다.
- 사용자는 기기를 오가는 일을 싫어하고, Claude가 커밋·푸시까지 끝내 주는 것을 선호한다 [사용자발언].
- 이 세션의 Claude에게는 이미지 생성 도구가 없었다. 도트 에셋은 코드로 픽셀을 직접 찍어 만들었다. 이미지 생성 도구가 있는 환경이라면 에셋 품질을 올릴 여지가 있다 [추측].
- 이 AI 환경에서는 Godot를 직접 실행하지 못했다. 가능한 환경이라면 헤드리스 실행으로 스크립트 오류를 미리 잡는 것이 좋다 [추측: 시도해 보지 않음].
